Each module is documented through both user interface interaction workflows and core technical implementations, supported by production code snippets, database schemas, and background job algorithms.

\subsection{Technology Stack and Architectural Infrastructure}

The BkLib platform is architected as a decoupled, multi-tier system composed of three primary software tiers: a client Single-Page Application (SPA) built with React and Vite, a core API Gateway and Business Logic service implemented in Node.js/Express with Prisma ORM, and a dedicated AI Microservice powered by Python, FastAPI, Google Gemini, and ChromaDB.

\subsubsection{Front-end Presentation Layer: React.js and Vite}
The front-end user experience is implemented as a modern Single-Page Application (SPA) using React.js 18 paired with the Vite build toolchain. Vite delivers instantaneous Hot Module Replacement (HMR) and highly optimized ES module bundling for production deployment. The presentation layer employs declarative component hierarchies, React Router DOM for client-side role-guarded routing, and Axios interceptors for automated JWT injection and token refresh. On the client side, components manage optimistic UI updates, debounced catalog search inputs, multi-channel notification bells, real-time circulation status indicators, and an embedded floating AI assistant widget with streaming responses.

\subsubsection{Back-end Core Server: Node.js and Express}
The core application server is constructed upon Node.js and the Express framework using TypeScript. It functions as the central API gateway and orchestrator for business logic, catalog management, circulation rules, user accounts, and session administration. The server enforces a modular, layered software architecture comprising Controllers, Services, Middlewares, and Background Cron Jobs. It delegates AI inference tasks (RAG context querying, document embedding generation, personalized recommendations) to the dedicated Python AI service via secure internal HTTP endpoints authenticated through shared secret tokens (\texttt{X-Internal-Key}).

Its key responsibilities include generating vector embeddings via pre-trained Transformer models, executing semantic book search with cosine similarity, coordinating Retrieval-Augmented Generation (RAG) over library regulations and FAQ repositories, and driving function-calling tools that bridge patron inquiries with live database records.

\subsubsection{Vector Store and Embedding Infrastructure: ChromaDB and Multilingual Models}
Text embedding representations for library documents, summaries, and FAQ knowledge bases are managed through a dual-vector architecture:
\begin{itemize}
    \item \textbf{In-Memory Vector Database (ChromaDB):} Serves as the high-speed vector retrieval engine for the library's official rules and FAQ documentation. The FAQ corpus is partitioned into overlapping chunks (400 characters, 60-character overlap) and indexed into ChromaDB collections during application startup.
    \item \textbf{High-Dimensional Embeddings:} Generated via \texttt{SentenceTransformer} utilizing the \texttt{paraphrase-multilingual-MiniLM-L12-v2} model (384-dimensional dense vectors) or Google Gemini's \texttt{models/text-embedding-004} (768-dimensional dense vectors). This enables bilingual semantic matching across Vietnamese and English bibliographic records.
\end{itemize}

\subsubsection{Adaptive Hybrid Search Strategy}
To overcome the limitations of pure keyword search (which fails on synonyms and conceptual phrasing) and pure vector search (which can miss exact ISBNs, call numbers, or proper nouns), BkLib implements an \textbf{Adaptive Hybrid Search Engine}. The engine computes a unified composite score:
\begin{equation}
    S_{\text{hybrid}} = w_{\text{semantic}} \cdot S_{\text{cosine}} + w_{\text{keyword}} \cdot S_{\text{overlap}}
\end{equation}
The weights $w_{\text{semantic}}$ and $w_{\text{keyword}}$ dynamically adjust according to query token count:
\begin{itemize}
    \item \textbf{Short Queries ($<3$ tokens):} $w_{\text{semantic}} = 0.40, w_{\text{keyword}} = 0.60$ (prioritizing exact title/author matching).
    \item \textbf{Medium Queries ($3-5$ tokens):} $w_{\text{semantic}} = 0.65, w_{\text{keyword}} = 0.35$ (balanced conceptual and keyword weighting).
    \item \textbf{Long Queries ($>5$ tokens):} $w_{\text{semantic}} = 0.80, w_{\text{keyword}} = 0.20$ (heavily favoring semantic intent).
\end{itemize}

\subsubsection{Security, Authentication, and Role-Based Access Control}
System security is established on four pillars:
\begin{itemize}
    \item \textbf{Stateless JWT Sessions:} Access tokens are signed using HMAC-SHA256 with short lifespans (15 minutes), supplemented by refresh tokens stored in HTTP-only cookies or secure headers for session persistence.
    \item \textbf{Bcrypt Hashing:} Passwords undergo salted Bcrypt hashing with configurable rounds (\texttt{BCRYPT\_ROUNDS = 10}).
    \item \textbf{Brute-Force Account Lockout:} Accounts incurring five consecutive failed authentication attempts are automatically locked for fifteen minutes (\texttt{lockedUntil}).
    \item \textbf{Granular RBAC:} Enforces role barriers across three hierarchical roles: \texttt{READER}, \texttt{LIBRARIAN}, and \texttt{ADMIN}.
\end{itemize}

\subsubsection{External Integrations: Open Library, Google Books, and Nodemailer}
\begin{itemize}
    \item \textbf{Bibliographic APIs (Google Books, Open Library, IT Bookstore):} Automated fallback cascade that enriches catalog records with cover images, publishers, publication years, and descriptions upon ISBN entry.
    \item \textbf{Transactional Messaging (Nodemailer):} SMTP integration delivering HTML emails for 6-digit OTP verification, loan approvals, pickup readiness notices, and due date alerts.
\end{itemize}

// Middleware verifying JWT access token from Authorization header
export const authenticate = (req: Request, res: Response, next: NextFunction): void => {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    res.status(401).json({ success: false, message: 'Khong co token xac thuc' });
    return;
  }
  const token = authHeader.split(' ')[1];
  try {
    const decoded = jwt.verify(token, env.JWT_SECRET) as AuthPayload;
    req.user = decoded;
    next();
  } catch (err) {
    if (err instanceof jwt.TokenExpiredError) {
      res.status(401).json({ success: false, message: 'Token da het han' });
    } else {
      res.status(401).json({ success: false, message: 'Token khong hop le' });
    }
  }
};

// Middleware factory restricting endpoint access to specified roles
export const authorize = (...roles: Role[]) => {
  return (req: Request, res: Response, next: NextFunction): void => {
    if (!req.user) {
      res.status(401).json({ success: false, message: 'Chua xac thuc' });
      return;
    }
    if (!roles.includes(req.user.role)) {
      res.status(403).json({ success: false, message: 'Khong co quyen truy cap' });
      return;
    }
    next();
  };
};
\end{lstlisting}

export const forgotPassword = async (email: string) => {
  const user = await prisma.user.findUnique({ where: { email } });
  if (!user) throw createError('Email khong ton tai trong he thong', 404);

  // Invalidate any existing unused reset tokens for this user
  await prisma.otpToken.updateMany({
    where: { userId: user.id, type: 'RESET_PASSWORD', usedAt: null },
    data: { usedAt: new Date() },
  });

  // Generate 6-digit random numeric token
  const otpToken = Math.floor(100000 + Math.random() * 900000).toString();
  const expiresAt = new Date(Date.now() + OTP_EXPIRES_MINUTES * 60 * 1000);

  await prisma.otpToken.create({
    data: { userId: user.id, token: otpToken, type: 'RESET_PASSWORD', expiresAt },
  });

  await sendResetPasswordEmail(email, otpToken, OTP_EXPIRES_MINUTES);
  return { message: 'Ma OTP da duoc gui den email cua ban' };
};
\end{lstlisting}

def retrieve_context(query: str, top_k: int = 3) -> str:
    """
    Retrieve top-k relevant text chunks for a query from ChromaDB vector collection.
    Formats results with segment headers to feed into LLM prompt context.
    """
    global _collection
    if _collection is None or _collection.count() == 0:
        return ""

    embedder = get_embeddings()
    query_embedding = embedder.encode([query]).tolist()

    results = _collection.query(
        query_embeddings=query_embedding,
        n_results=min(top_k, _collection.count()),
    )
    docs = results.get("documents", [[]])[0]
    if not docs:
        return ""

    return "\n\n---\n\n".join([f"[Doan {i+1}]: {doc}" for i, doc in enumerate(docs)])
\end{lstlisting}

async def execute_tool(tool_name: str, args: dict[str, Any]) -> str:
    """
    Execute tool requested by Gemini by calling internal Node.js backend endpoints.
    Returns textual result to inject back into the LLM context.
    """
    user_id = args.get("user_id", "")
    headers = {"X-Internal-Key": settings.INTERNAL_API_KEY}

    async with httpx.AsyncClient(timeout=10.0) as client:
        try:
            if tool_name == "get_active_borrows":
                res = await client.get(
                    f"{settings.BACKEND_URL}/api/v1/ai/internal/user/{user_id}/borrows",
                    headers=headers,
                )
                if res.status_code == 200:
                    data = res.json().get("data", [])
                    if not data:
                        return "Nguoi dung hien khong co sach nao dang muon."
                    lines = [f"- '{b['title']}' (Han tra: {b['dueDate']})" for b in data]
                    return f"Dang muon {len(data)} cuon sach:\n" + "\n".join(lines)

            elif tool_name == "get_user_fines":
                res = await client.get(
                    f"{settings.BACKEND_URL}/api/v1/ai/internal/user/{user_id}/fines",
                    headers=headers,
                )
                if res.status_code == 200:
                    data = res.json().get("data", {})
                    total = data.get("totalFines", 0)
                    return f"Tong tien phat chua thanh toan: {total:,}d."
        except Exception as e:
            print(f"[Function Tool Error] {tool_name}: {e}")
    return "Khong the lay du lieu tu he thong luc nay."

export const renewBorrowRecord = async (borrowRecordId: string, userId: string) => {
  const borrowRecord = await prisma.borrowRecord.findUnique({
    where: { id: borrowRecordId },
    include: { physicalCopy: { include: { book: true } } },
  });

  if (!borrowRecord) throw createError('Khong tim thay phieu muon', 404);
  if (borrowRecord.userId !== userId) throw createError('Khong co quyen gia han', 403);
  if (borrowRecord.status !== BorrowStatus.ACTIVE) {
    throw createError('Phieu muon khong con hieu luc', 422);
  }

  // Prevent online renewal if item is already overdue
  const now = new Date();
  if (now > borrowRecord.dueDate) {
    throw createError('Sach da qua han, khong the gia han truc tuyen.', 422);
  }

  // Verify renewal attempt cap
  const maxRenew = parseInt(await getConfig(CONFIG_KEYS.MAX_RENEW, '2'), 10);
  if (borrowRecord.renewCount >= maxRenew) {
    throw createError(`Da dat gioi han gia han toi da (${maxRenew} lan)`, 422);
  }

  // Block renewal if other patrons are waiting in queue
  const hasReservation = await prisma.reservation.count({
    where: {
      bookId: borrowRecord.physicalCopy.bookId,
      userId: { not: userId },
      status: { in: [ReservationStatus.WAITING, ReservationStatus.READY_FOR_PICKUP] },
    },
  });
  if (hasReservation > 0 && borrowRecord.physicalCopy.book.availableCopies === 0) {
    throw createError('Tai lieu dang co nguoi dat giu cho. Vui long tra dung han.', 422);
  }

  const renewDays = parseInt(await getConfig(CONFIG_KEYS.RENEW_DURATION, '7'), 10);
  const newDueDate = new Date(borrowRecord.dueDate);
  newDueDate.setDate(newDueDate.getDate() + renewDays);

  await prisma.borrowRecord.update({
    where: { id: borrowRecordId },
    data: { dueDate: newDueDate, renewCount: { increment: 1 } },
  });

  return { message: 'Gia han thanh cong', newDueDate, renewCount: borrowRecord.renewCount + 1 };
};

const calcOverdueDays = async (dueDate: Date, returnDate: Date): Promise<number> => {
  if (returnDate <= dueDate) return 0;

  // Retrieve official holiday array configured in system settings
  const holidayConfig = await getConfig(CONFIG_KEYS.HOLIDAY_DATES, '[]');
  const holidays: string[] = JSON.parse(holidayConfig);

  let overdueDays = 0;
  const cursor = new Date(dueDate);
  cursor.setDate(cursor.getDate() + 1);

  // Day-by-day iteration excluding official calendar holidays
  while (cursor <= returnDate) {
    const year = cursor.getFullYear();
    const month = String(cursor.getMonth() + 1).padStart(2, '0');
    const day = String(cursor.getDate()).padStart(2, '0');
    const dateStr = `${year}-${month}-${day}`;

    if (!holidays.includes(dateStr)) {
      overdueDays++;
    }
    cursor.setDate(cursor.getDate() + 1);
  }
  return overdueDays;
};
\end{lstlisting}

export const fetchBookInfoByIsbn = async (isbn: string): Promise<ExternalBookInfo | null> => {
  const cleanIsbn = isbn.replace(/[-\s]/g, '');

  // 1. Query Google Books API
  try {
    const response = await axios.get('https://www.googleapis.com/books/v1/volumes', {
      params: { q: `isbn:${cleanIsbn}` },
      timeout: 5000,
    });
    if (response.data.totalItems > 0) {
      const info = response.data.items[0].volumeInfo;
      return {
        title: info.title,
        authorNames: info.authors || [],
        publisher: info.publisher,
        publishYear: info.publishedDate ? parseInt(info.publishedDate.substring(0, 4)) : undefined,
        language: info.language,
        description: info.description,
        coverImageUrl: info.imageLinks?.thumbnail?.replace(/^http:/, 'https:'),
        isbn: cleanIsbn,
      };
    }
  } catch (error) { /* Fallback to Open Library on error or rate-limit */ }

  // 2. Fallback to Open Library API
  try {
    const olRes = await axios.get(
      `https://openlibrary.org/api/books?bibkeys=ISBN:${cleanIsbn}&format=json&jscmd=data`,
      { timeout: 5000 }
    );
    const olData = olRes.data[`ISBN:${cleanIsbn}`];
    if (olData) {
      return {
        title: olData.title,
        authorNames: olData.authors?.map((a: any) => a.name) || [],
        publisher: olData.publishers?.map((p: any) => p.name).join(', '),
        publishYear: olData.publish_date ? parseInt(olData.publish_date.match(/\d{4}/)?.[0]) : undefined,
        description: olData.notes,
        coverImageUrl: olData.cover?.medium || olData.cover?.large,
        isbn: cleanIsbn,
      };
    }
  } catch (error) { /* End of cascade */ }
  return null;
};
\end{lstlisting}

export const startReservationExpiryJob = () => {
  // Execute daily at 01:00 AM
  cron.schedule('0 1 * * *', async () => {
    const now = new Date();
    const expired = await prisma.reservation.findMany({
      where: {
        status: ReservationStatus.READY_FOR_PICKUP,
        expiresAt: { lt: now },
      },
      include: { book: true },
    });

    for (const reservation of expired) {
      // 1. Mark reservation as EXPIRED
      await prisma.reservation.update({
        where: { id: reservation.id },
        data: { status: ReservationStatus.EXPIRED },
      });

      // 2. Re-assign physical copy to next waiting patron or return to AVAILABLE
      const nextInQueue = await prisma.reservation.findFirst({
        where: { bookId: reservation.bookId, status: ReservationStatus.WAITING },
        orderBy: { queuePosition: 'asc' },
      });

      if (nextInQueue) {
        await prisma.reservation.update({
          where: { id: nextInQueue.id },
          data: {
            status: ReservationStatus.READY_FOR_PICKUP,
            expiresAt: new Date(now.getTime() + 3 * 24 * 60 * 60 * 1000),
          },
        });
      } else {
        await prisma.physicalCopy.updateMany({
          where: { bookId: reservation.bookId, status: CopyStatus.RESERVED },
          data: { status: CopyStatus.AVAILABLE },
        });
        await prisma.book.update({
          where: { id: reservation.bookId },
          data: { availableCopies: { increment: 1 } },
        });
      }
    }
  });
};

export const restoreBackup = async (filename: string, userId: string) => {
  const filePath = getBackupFilePath(filename);
  if (!fs.existsSync(filePath)) throw createError('File sao luu khong ton tai', 404);

  const snapshot = JSON.parse(fs.readFileSync(filePath, 'utf8'));
  const systemConfigs = snapshot.systemConfigs ?? [];
  const branches = snapshot.branches ?? [];

  // Execute restore within an atomic ACID transaction
  await prisma.$transaction(async (tx) => {
    for (const config of systemConfigs) {
      await tx.systemConfig.upsert({
        where: { key: config.key },
        create: { key: config.key, value: config.value, description: config.description },
        update: { value: config.value, description: config.description },
      });
    }

    for (const branch of branches) {
      await tx.branch.upsert({
        where: { id: branch.id },
        create: {
          id: branch.id, name: branch.name, address: branch.address,
          phone: branch.phone, managerId: branch.managerId, isActive: branch.isActive,
        },
        update: {
          name: branch.name, address: branch.address,
          phone: branch.phone, managerId: branch.managerId, isActive: branch.isActive,
        },
      });
    }
  });

  // Record audit trail entry for critical restore operation
  await prisma.auditLog.create({
    data: {
      userId, action: AuditAction.CONFIG_CHANGE,
      entityType: 'Restore', entityId: filename, riskLevel: 'CRITICAL',
    },
  });

  return { message: 'Da phuc hoi cau hinh va chi nhanh thanh cong' };
};

\subsection{Deployment Stage}

This section describes the deployment strategy and infrastructure setup for the project. The system is distributed across different cloud providers to leverage their specific strengths: Vercel for the frontend and Express backend due to its seamless CI/CD integration and serverless architecture, and Google Cloud Run for the AI service to handle containerized machine learning workloads efficiently.

\subsubsection{Frontend Deployment}
The frontend application, built with React and Vite, is deployed on Vercel. Vercel provides a global Edge Network that ensures fast content delivery and high availability. The deployment process is integrated directly with the GitHub repository. Upon every push to the main branch, Vercel automatically triggers a new build process, executing the production build script, and updates the live website. Environment variables, such as backend API URLs, are securely managed within the Vercel dashboard.

\subsubsection{Backend Deployment}
The backend service, built with Node.js and Express, is also deployed on Vercel, utilizing Serverless Functions. This approach eliminates the need for manual server provisioning and scales automatically based on incoming traffic.
To configure the deployment, a \texttt{vercel.json} file is utilized at the root of the backend directory to specify the build environment and routing rules. The configuration directs all incoming API requests to the main application entry point \texttt{src/app.ts}, utilizing the \texttt{@vercel/node} runtime:

\begin{verbatim}
{
  "version": 2,
  "builds": [
    {
      "src": "src/app.ts",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/(.*)",
      "dest": "src/app.ts"
    }
  ]
}
\end{verbatim}
This setup allows Express routing to function seamlessly within a serverless environment.

\subsubsection{AI Service Deployment}
The AI service, which handles resource-intensive tasks such as natural language processing and semantic search, is developed in Python. It requires a specific runtime environment with complex dependencies defined in \texttt{requirements.txt}. To ensure consistency across environments, it is containerized using Docker and deployed to Google Cloud Run.

\begin{itemize}
    \item \textbf{Containerization:} A \texttt{Dockerfile} is utilized to package the Python application, its system dependencies, and Python packages into a standardized Docker image.
    \item \textbf{Google Cloud Run:} Cloud Run is a fully managed compute platform that automatically scales stateless containers. It is chosen for the AI service because it can efficiently provision the necessary CPU and memory resources for inference requests and scales down to zero when idle, optimizing operational costs.
    \item \textbf{Deployment Process:} The Docker image is built and pushed to Google Artifact Registry. A Cloud Run service is then deployed referencing the uploaded image. The service is securely configured with necessary environment variables and allocated sufficient resources to handle concurrent AI workloads.
\end{itemize}

\subsubsection{System Integration}
The decoupled deployment architecture ensures that each service can scale independently based on its specific load. The frontend communicates with the Vercel-hosted Express backend via standard HTTPS RESTful APIs. The Express backend, in turn, forwards specialized AI requests to the Google Cloud Run endpoint, acting as an API gateway. This modular deployment strategy enhances fault tolerance, maintainability, and scalability.
